# Repository index

- `ThDarkOrbitEmulator.ApiService/Features/`: HTTP endpoints and world TCP listener; Unity login and resources are implemented here.
- `ThDarkOrbitEmulator.Identity.*`: account and cockpit catalog persistence; SQL migrations in `Identity.Infrastructure/Migrations/Sql/`.
- `ThDarkOrbitEmulator.Tests/ClientTesting/`: focused Unity contract and world protocol tests; `Integration/` holds database and HTTP integration tests.
- `docs/cockpit-catalog.md`: cockpit evidence, unresolved native contracts, and public catalog routes.
- `docs/client-endpoint-map.md` and `docs/world-protocol.md`: observed client endpoints and provisional local world protocol.
- `docs/reference-parity.md`: ranked gameplay gaps from ignored third-party reference clones; iterations 1–2 add NPC pursuit and sustained fire, iteration 3 adds a shared ten-second portal combat lock, iteration 4 gives generated loot a distinct ID per respawn cycle, iteration 5 broadcasts loot visibility changes, iteration 6 restores NPC shields, iteration 7 restores pilot shields, iteration 8 returns disengaged NPCs to patrol, iteration 9 adds per-template passive NPC aggression, iteration 10 gives killed NPCs independent respawn timers and reward generations, and iteration 11 restores pilot hull while stationary and out of combat.
- `ApiService/Features/World/WorldCollectibleVisibility.cs`: computes map-owner box removals and creations across pickup and respawn cycles for TCP broadcasts.
- `_reversing/`: local analysis artifacts and captured sessions; `scripts/client-testing/` contains capture helpers.
- `_reversing/Analysis/trace_il2cpp.py`: bounded native disassembly using the ignored `il2cpp-dump/` method map; findings are recorded in `docs/cockpit-catalog.md`.
- `ThDarkOrbitEmulator.AppHost/`: Aspire wiring, including HTTPS and world listener ports.
- `ThDarkOrbitEmulator.Tests/Integration/WorldAssignedHangarPostgresTests.cs`: PostgreSQL cockpit assignment to world stat entry regression.
- `ApiService/Features/UnityApi/Login/UnityHangarActivateAction.cs`: installed `config.txt` `hangerChange:/unityApi/activate.php` POST (`hangarId` form, JSON `success`/`message`) selects the player's assigned PostgreSQL hangar; mapped in `CockpitCatalogEndpoints.cs` and covered by `UnityHangarActivatePostgresTests.cs`.
- `ApiService/Features/UnityApi/Login/UnityConfigRoutes.cs`: maps the seven remaining installed `config.txt` endpoints (instance, close, agent, changeInstance, evoucher, package, setLang) with game-session checks; `UnityHangarActivatePostgresTests.cs` covers them through HTTP and PostgreSQL. The complete twelve-template table and native callback trace are in `docs/cockpit-catalog.md`.
- `ThDarkOrbitEmulator.Tests/Integration/WorldRocketAndNpcAggroTests.cs`: shared-cache rocket cooldown, lethal reward, NPC pursuit and pilot damage integration tests.
- `ApiService/Features/World/NativeWorldHandshake.cs`: native Unity three-byte framing, version and login modules, session authentication, and provisional map/hero entry payloads; loopback coverage in `WorldTransportTests.cs`.
- `.ralph/memory-index.json`: focused world entry, transport, simulation, and test paths; records the currently missing requested spec files.
- `docs/specs/03-hangar-inventory-and-shop.md`, `07-economy-progression-and-quests.md`, `08-clans-diplomacy-and-chat.md`: topical Task 3 audits supplement the existing numbered master specs. Shop, Dock, Skylab, and Galaxy Gates live in `ApiService/Features/IndexInternal/InternalStart/` with durable mutations in `ApiService/Features/Economy/EconomyStore.cs`; Cockpit routes live in `ApiService/Features/UnityApi/Login/CockpitCatalogEndpoints.cs`.
- `ApiService/Features/Economy/EconomyProgression.cs`: timed collector upgrades and refinery batches. `ApiService/Features/Economy/GalaxyGateCombat.cs` owns durable NPC wave composition, server-calculated gate attacks, life loss, and atomic completion rewards; `IndexInternal/InternalStart/LocalProgressionAction.cs` and `LocalProgressionPanel.cs` expose signed menu forms. Schema migrations: `Identity.Infrastructure/Migrations/Sql/031_skylab_jobs_and_gate_waves.*.pgsql` and `033_gate_combat.*.pgsql`; integration coverage lives in the Skylab and Galaxy Gate PostgreSQL fixtures.
- `ApiService/Features/World/WorldGateCombat.cs`: account-scoped Galaxy Gate NPC roster and world target/shot adapter to durable gate runs. `WorldState.cs` adds faction gate maps and portal eligibility; `WorldHttpBridge.cs` and `WorldSessionHandler.cs` expose gate combat in HTTP and local TCP. `GameAuthSessionStore.cs` persists selected `InstanceId` from Unity login/changeInstance; `NativeWorldHandshake.cs` and local TCP login compare it against the socket request. Coverage: `LocalGalaxyGatePostgresTests.cs` and `WorldTransportTests.cs`.
- `ApiService/Features/Economy/EconomyClanOperations.cs` and `IndexInternal/InternalStart/LocalClanOperations.cs`: Task 7 leader-scoped diplomacy and station modules; migration `032_clan_diplomacy_stations.*.pgsql`; PostgreSQL coverage in `LocalClanPostgresTests.cs`.
- `IndexInternal/InternalStart/LocalHangarEquipmentSelection.cs` and `EconomyStore.cs`: Task 7 atomic Dock transfer between ships, covered by `EconomyPostgresTests.cs`.
- `ApiService/Features/Backoffice/Progression/ProgressionBackofficeEndpoints.cs`: admin-only inspection and bounded overrides for active hangars, Skylab job deadlines, unfinished Galaxy Gate combat state, clan station modules, and diplomacy records. The Angular `Cms/src/app/features/backoffice/progression/` view consumes these routes; `ProgressionBackofficePostgresTests.cs` covers persisted HTTP behavior.
- `scripts/admin/Start-AdminCli.ps1` launches `scripts/admin/admin-cli.mjs`; `/hangar`, `/skylab`, `/gate`, and `/clan` call the progression backoffice routes directly with Tab suggestions. Progression now exposes explicit Skylab timer readiness and Galaxy Gate wave reset/completion actions; `ThDarkOrbitEmulator.Tests/Backoffice/AdminCliProgressionTests.cs` covers CLI parsing and completion.

Read the relevant feature directory and documentation before broader searches. Update this index when adding or moving modules.
