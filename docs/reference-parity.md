The two shallow clones under ignored `_reference/` are comparison material, not dependencies or native Unity evidence. `darkorbit-emulators` contains several older server implementations; `Darkorbit-client` is a Flash wrapper and packet inspection tool, not a gameplay server. Their packet identifiers and framing must not be copied into the provisional Unity world protocol without a captured fixture. The relevant local contract is [world-protocol.md](world-protocol.md).

The rank reflects gameplay impact and an implementable local slice. The Flash reference does not establish the installed Unity client's wire contract. No reference source is copied into the emulator.

Iteration 2 kept rocket fire as a single cooldown-gated action and reused the existing authoritative NPC hit and reward path for each timed laser shot. `WorldNpcs` stores active fire in the shared cache so the map lease owner can advance it after a node handoff. The TCP start request still emits its immediate hit and result; subsequent hits arrive through existing damage broadcasts. Focused tests cover timing, explicit stop, target-lock change, range loss, and socket acceptance of the stop command. The second slice preserves the NPC's current target while it remains eligible and tests peace-zone retargeting. The next ranked implementation gap is the portal combat restriction (rank 4).

Iteration 3 records combat time only after a successful NPC attack or an applied NPC hit. `WorldSessionStore.JumpAsync` checks the shared marker while holding its map mutation lock and before persisting a new map. The ten second window uses server time and ends exactly at its boundary. Gate map exits remain exempt, allowing departure from a gate run. Tests cover an outgoing attack across two session-store replicas, the expiry boundary, and an incoming hit. The reference restricts only PvP maps; our synthetic faction maps have no PvP flag, so the broader standard-map policy is a local rule pending native capture.

Iteration 4 gives generated boxes distinct positive 32-bit IDs for each map, respawn cycle, and slot (16 maps, 65,536 cycles, 1,000 slots). The shared claim key still includes the full cycle. A stale pickup now returns `missing` rather than crediting a replacement, and tests cover the cycle boundary. The reference's cargo drop occurs on player destruction, so it does not establish an NPC drop requirement. The next local gameplay gap is generated loot respawn visibility to connected TCP clients (rank 6).

Iteration 5 has the map lease owner compare the complete visible box roster with the IDs it last announced. It sends removal packets for IDs that disappeared, then creation packets for new IDs. This covers generated cycle replacement, shared pickups, and manual box changes while preserving map-scoped observers. A focused test checks initial appearance, no duplicate announcement, cycle replacement, and a claimed box. The next ranked gap is native movement and packet compatibility (rank 7), which requires a Unity capture before wire changes.

Iteration 6 adds NPC shield recovery as the next implementable gameplay slice while movement packet compatibility still awaits native Unity evidence. The reference's `Npc.CheckShieldPointsRepair` motivated the local rule; its packet code was not copied. The map-owner simulation restores one tenth of an NPC's maximum shield per second after ten seconds since the last player hit. It caps recovery at maximum and resets the quiet period on every successful hit. Shared vitality makes the recovered shield visible across replicas, and invalidating the observer snapshot lets sockets see the changed value. A focused test covers the delay, interval, reset, and cap. `Darkorbit-client` remains useful for packet inspection only and supplies no server-side shield behavior.
