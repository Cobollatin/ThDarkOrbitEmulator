# SPEC-04: Out-of-Game Menus 1–15

## Boundary and authority

These are emulator pages under `GET /indexInternal.es?action=…` and form actions under `POST /indexInternal.es?action=…`. They do not establish official Unity menu contracts. `Features/IndexInternal/InternalStart/IndexInternalStartEndpoint.cs` dispatches the route; each `Local*Action` owns validation. The `dosid` cookie identifies the pilot. Mutating forms carry a session-bound, time-limited key and generally redirect with HTTP 303. Pages return HTML with `Cache-Control: no-store`. Unknown, duplicate, control-character-bearing, or overlong query parameters yield 400. Syntactically valid unknown catalog selections generally yield 404 after authentication. Missing sessions yield 401; pilots without a company are redirected to company choice. Individual handlers determine precedence when multiple errors exist.

The table lists page-specific parameters. Several pages also accept `from`, `prc`, and `lang` as single navigation values of at most 64 characters. These never mutate state. Notice parameters are generated by redirects and checked against saved state. Search is read-only. Account state is in the distributed cache or economy database.

## Common validation and persistence rules

1. A GET page renders current state; notice query values are not proof of mutation. User-controlled text is HTML-encoded.
2. POST action queries contain exactly one canonical lowercase `action` key. Wrong methods yield 405. Signed forms bind to the session; an expected slot, level, revision, job or item protects against stale tabs. Equipment uses exact fields and current inventory rather than a signed form key.
3. Saved state is account-scoped. A new store instance over the same distributed cache reads the change; database-backed Shop, Assembly and Auction use the economy service in the routed endpoint.
4. Page query values are singletons. Numeric IDs that require canonical syntax reject leading zero, sign, whitespace and overflow. Each menu's validator applies further semantic checks.
5. The CMS and emulator-rewritten portal retain their generic placeholder titles; these menu routes do not authorize branding changes in those surfaces.

### Numeric and temporal boundaries

| Input | Accepted boundary |
|---|---|
| Hangar and equipment slot/configuration | Exact ASCII `1` or `2`. |
| Equipment assignment quantity | Canonical decimal `0`–`999`; zero removes that item's assignment. |
| Shop purchase quantity | Canonical decimal `1`–`100`. |
| Pilot skill rank | At most 5 for a default skill; individual skill definitions may set a lower maximum. |
| Skylab collector level | 1–10. A current level of 10 cannot be upgraded. |
| Galaxy Gate spin amount | Canonical decimal `1`–`10` per form. |
| Auction bid | Positive decimal, at most nine digits; next minimum is opening bid or current bid plus at least 10% (minimum increment 1). |
| Message/contact ID | Positive decimal of at most nine digits with no leading zero. |
| Message subject/body | Trimmed subject 1–60 characters; body at most 500 characters. Sending requires the recipient to be a saved friend. |
| Signed menu form lifetime | One hour, with up to five minutes of forward clock skew, for Shop, Hangar, Clan, Pilot Sheet, Tech Factory, Skylab, Galaxy Gates, Assembly, Auction, Quests and Messaging. Expired forms yield a conflict; malformed keys yield 400. |

### Hangar selection POST guard order and time boundary

`LocalHangarSelection.HandleAsync` accepts `POST /indexInternal.es?action=internalDockSelect` only. It checks the action, method, and single canonical lowercase `action` query before looking up the `dosid` session. Missing sessions return 401; a session without a valid company returns 403. These checks run before content type and form parsing, so an unauthenticated malformed form cannot reach the form reader. The action query guard returns 404 for a different action, 405 for a wrong method on the correct action, and 400 for an extra or differently cased query key.

After authentication, the request must have form content type and exactly one nonblank value for each of `slot`, `current`, and `key`, with no other form fields. Both slots use canonical `1` or `2` and must differ. A malformed or incorrectly bound key returns 400. A signed issue time more than five minutes ahead returns 400; exactly five minutes ahead is accepted. A key older than one hour returns 409; exactly one hour old is accepted. The slot change is a compare-and-set against `current`, so replay and stale forms return 409. A successful change returns 303 with `Location: /indexInternal.es?action=internalDock&activated=<slot>` and `Cache-Control: no-store`. Rejected requests leave the active slot unchanged.

### Query, identifier and redirect edge-case contract

1. **Action queries.** Shop, Clan, Pilot Sheet, Messaging, Galaxy Gates and Assembly POST queries are valid only when the query has exactly one key, spelled `action` in lowercase, with one value. An extra key, `ACTION`, a repeated value or a missing key fails. Galaxy Gates accepts only `internalGalaxyGateSpin` and `internalGalaxyGateActivate`; Assembly only `internalAssemblyCraft`. The other four validators check only the query shape; the handler then dispatches on the value.
2. **Navigation values.** `from`, `prc` and `lang` have at most 64 characters. Hangar, Shop, Clan, Pilot Sheet and Messaging accept 64 and reject 65. A control character or a repeated value is rejected on Hangar, Shop, Clan, Pilot Sheet, Galaxy Gates and Messaging. All fifteen page validators reject a repeated `action` value.
3. **Hangar slot.** `TryParseSlot` accepts only the strings `1` and `2`. `0`, `3`, `01`, ` 1`, `+1`, empty and null fail and return slot 0.
4. **Hangar form key.** Format: `<32-hex nonce>.<unix seconds>.<64-hex HMAC-SHA256>`. The key is signed with the `dosid` and binds the requested slot and the slot that was active when the page was rendered. `KeyIssued` returns the issue time only for an exact match. It returns null for another session, another requested slot, a changed active slot, a tampered signature, extra segments or an empty key. Each call makes a fresh nonce, so two keys for the same inputs differ.
5. **Notices.** Hangar `activated` must be a valid slot. Pilot Sheet `reset` must be exactly `1`, and `trained` cannot appear with `reset`. Galaxy Gates `spun` and `activated` exclude each other. Messaging allows at most one of `sent`, `deleted`, `added`, `removed`, `readall`. `readall` must be `1`; the others must be canonical IDs. `NoticeOf` returns the single notice and its value (`readall` gives 1), or null when there is none.
6. **Search syntax differs per menu.** Shop and Messaging `q` must already be trimmed and have 2–40 characters with no control characters; edge whitespace is rejected, not trimmed. Galaxy Gates and Assembly treat a blank `q` as no search. Otherwise Galaxy Gates trims the value, then requires 2–40 ASCII letters, digits, spaces, `-` or `_`; `Search` returns the trimmed text or null. Clan `q` has 1–32 ASCII letters, digits, spaces or hyphens, with no edge spaces.
7. **Search and detail.** On Galaxy Gates (`gate`) and Assembly (`detail`), a nonblank `q` together with the detail key fails. A blank `q` with the detail key is accepted.
8. **Identifiers.** Clan IDs have 1–64 characters: lowercase ASCII letters and digits, joined by single hyphens, with no leading or trailing hyphen. Skill IDs start with a lowercase ASCII letter, followed only by ASCII letters or digits. Recipe IDs have 1–`MaxRecipeIdLength` (64) characters: lowercase ASCII letters, digits, `_` or `-`.
9. **Success redirects.** Successful actions redirect to these locations:
   - `internalDock&activated=<slot>`
   - `internalClan&joined=<clan>` or `internalClan&left=<clan>`
   - `internalPilotSheet&reset=1` or `internalPilotSheet&trained=<skill>`
   - `internalGalaxyGates&spun=<gate>` or `internalGalaxyGates&activated=<gate>`

   Galaxy Gates adds `&filter=<filter>` unless the filter is null or `all`. Every redirect location must pass its own page validator.

## Verification and limits

`ClientTesting/Menus1To15SpecificationTests.cs` covers route validation, numeric boundaries, the query, identifier and redirect edge-case contract above, read-only rankings and cache persistence. `ClientTesting/LocalHangarTests.cs` covers the Hangar POST guard order, exact form-time boundaries, replay and active-slot persistence. Existing `LocalShop*`, `LocalClan*`, `LocalPilot*`, `LocalTechFactory*`, `LocalSkylab*`, `LocalGalaxyGate*`, `LocalAssembly*`, `LocalAuction*`, `LocalQuest*`, `LocalMessaging*` and `LocalRankings*` suites cover deeper form and state cases. This establishes emulator behavior. A complete signed-in Unity WebView journey and official menu payloads remain unverified under the no-CA rule.
